Follow [Build Structure and Formula Flow](#build-structure-and-formula-flow) to show the work; do not hide an entire build in one dense formula or add trivial helpers just to make formulas shorter.\n- Keep raw data, editable assumptions, mappings and business rules in labeled cells or tables. Keep calculated results as formulas so they update with their inputs.\n- Fixed cutoffs or categories from the user's request can appear directly in formulas when result labels state the rule. Use one labeled input cell when the cutoff is user-adjustable or serves as a shared assumption across different calculations.\n- Calculate a shared result once and reuse it when the inputs, period, units, rounding and overrides match. Keep independent reconciliations independent.\n- Use consistent formulas across comparable rows and periods, while preserving intentional differences such as [historical versus forecast logic](domain_guidance/financial_models.md#periods-assumptions-and-scenarios), one-off adjustments and overrides.\n- Keep business calculations in the owning build and necessary input guards with their inputs or dependent build logic, following the [terminal Checks/Audit rule](#checks-and-audit). Anchor shared **rows, columns or individual cells** so the workbook can reuse one period header, assumption block, item column or Case selector instead of repeating it beside every calculation.\n\n| Reference | What stays fixed | Useful pattern |\n| --- | --- | --- |\n| `C8` | Neither row nor column | A quantity that moves with the calculation when copied across or down. |\n| `C$4` | Row 4 | Read each column's period from one shared header row; copying across advances the period, copying down keeps that header. |\n| `$A8` | Column A | Read each row's item or category from one shared column; copying down advances the item, copying across keeps its label. |\n| `$B$3` | Cell B3 | Reuse one fixed conversion rate or Case selector throughout the applicable calculation. |\n\nFor example, `=SUMIFS(Amount,Month,C$4,Item,$A8)` reads the period above and the item at the left. Use keyed lookups when source and destination orders differ; anchoring cannot make mismatched row positions equivalent. Quote cross-sheet names, for example `='Build'!E14`.\n\n### Dates and Time Periods\n\n- When calculations depend on a reporting date, use the date specified by the task or source. Check required factors first: `PRODUCT` ignores blank/text cells in a referenced range, which can make missing inputs look like a valid result.\n- **Conditional counts, sums and averages:** prefer `COUNTIFS`, `SUMIFS` and `AVERAGEIFS` for new formulas, even with one criterion, so another condition can be added consistently. Avoid choosing `COUNTIF`, `SUMIF` or `AVERAGEIF` for new work by default; preserve a valid existing/template convention during a narrow edit. This preference does not prohibit an ordinary `IF` condition.\n- **Lookups:** `INDEX/MATCH`, `VLOOKUP` and `XLOOKUP` are all useful. Follow the user's preference and the workbook's established approach where it works. Do not substitute a first-match lookup for a required sum.\n- **Conditional logic:** use a short `IF` for a simple choice. Preserve required existing/template behavior and do not rewrite unrelated formulas during a narrow edit. Formula length alone is not the test: the reader must be able to understand and extend the calculation.\n- **Sensitivity analysis:** use a native What-If Data Table only for an explicitly requested native sensitivity analysis or required existing/template behavior, when supported. Keep API setup and feature-specific execution details in the relevant tool reference.\n\n### Scalable Formulas and Brief Explanations\n\nUse the patterns below when they make recurring updates easier without hiding the calculation. Choose the simplest approach that supports the actual update workflow, not just the current snapshot.\n- **Assumption and Case selection:** prefer one numeric Case selector with labeled case names and `CHOOSE` or `OFFSET` to select the active assumptions. `INDEX/MATCH` or `XLOOKUP` remain valid when they fit the layout.
